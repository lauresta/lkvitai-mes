# Открытые вопросы переноса Gamyba

Статус на 2026-11-03. Сюда попадают только нерешённые вопросы из [реестра действий](legacy-production-coverage.md); решение фиксируется с доказательством, а закрытая строка удаляется из списка после переноса в реестр. Ниже нет разрешения менять общую production-базу или печатать на оборудовании.

| ID / сценарий | Вопрос и влияние | Следующий безопасный шаг |
|---|---|---|
| P01 · G02/G03 | Access строит дерево из `V_WaitingProductionBlinds`, а строки из `SP_fsubProduction`. Под `TERMINAL\d.bykovas` процедура дала 16 строк, view — 56; все 40 лишних строк view относятся к исключённой процедурой категории `985019188`. Оба объекта сами по себе не вызывают `Loc_leidimas`. | Stage 2 read API и фильтры считают по одному правилу процедуры с `Loc_leidimas().UKS`, поэтому счётчики web могут отличаться от дерева Access; сверить с оператором и решить, нужно ли менять старое дерево. |
| P02 · G03 | Access назначает GU через `DCount+1`; живой триггер `T_NewProductionOutputDocumentNo` нумерует только GT с пустым номером. Сейчас 7 819 GU без дублей и без unique-ограничения; среди остальных номеров есть 4 515 групп дублей, поэтому уникальность всей колонки невозможна. В текущей работе GU создаёт один оператор; параллельная выдача Access+web по подтверждению владельца не блокирует перенос. | Повторить нумерацию Access `DCount+1` в SQL под mapped login; web-команды сериализовать и после потери ответа проверять результат перед повтором. Не менять общую схему и не вводить новый формат номера. Если появится второй оператор, зафиксировать отдельный риск коллизии. |
| P03 · G03/G08 | Нужно подтвердить пределы добавления порций к текущему/историческому GU и допустимость пустого GU/GT. | Снять свойства формы, SQL-триггеры и эталон действий Access; зафиксировать атомарность каждой команды. |
| P04 · G01–G15 | Полный список меню/кнопок/контекстных действий и права на строки/поля пока не закрыт. `frmBlindsProduction` открыт через меню 49 `Nauja gamybos užduotis`, `frmMadeProductionDocuments` — через меню 41 `Gatava produkcija`; обе формы открывают `dlgPrintDocuments`. У `TERMINAL\d.bykovas` оба пункта включены; меню 49 выключено у одного из 36 legacy-пользователей. У `sa` записи нет, для Cikada admin сохранён явный bypass. `project.TBD_Forms` содержит лишь 9 форм и не включает производственную. | Серверная очередь и GU проверяют меню 49, наборы отчётов — 49 или 41, дополнительно к `Loc_leidimas`. Для прочих действий снять отдельные пункты меню, свойства форм/макросы и `project.TCR_UserFormControls`; расширить реестр. |
| D02 · G04 | Как показывать GU, если только часть состава доступна оператору, не решено. Read API пока полностью скрывает такой GU и пустые документы; прямой ID возвращает 404. Под другим существующим mapped SQL principal с более узкими филиалами прямые чужие barcode/GU и guarded dataset не вернули строк. | Сверить с Access и владельцем правило для смешанных и пустых GU; до решения не раскрывать частичный состав. |
| P05 · G05/G15 | Все 13 действующих `rptGamDok*` и общий подотчёт `rsubParduotiPriedai` экспортированы из текущего Access в `docs/shopfloor/access-report-layouts/`. Dataset web теперь включает связанные аксессуары, но это ещё не проверено на живом GU; PDF-рендерера 1:1 нет. `rptGamDokPleated.Report_Open` подменяет design-time `SP_GamPleatedByTask` на `SP_GamPlisuotasByTask`; web следует runtime. При открытии формы появилось `reikia block`, затем она открылась с пустым выбранным GU; PDF-образцы не получены. | Сверить аксессуары на живом GU; получить Access PDF-эталоны короткого/длинного/пустого случая; реализовать renderer из экспортированных макетов, сверить текст, группировку, страницы и визуал; затем обычную печать и архив. |
| P06 · G05 | Не установлено, доступны ли исходные PDF из двух старых UNC-архивов и нужен ли автоматический выбор обычного принтера. | Проверить существование и использование файлов/принтера на рабочем месте; исходный PDF не подменять регенерацией. |
| P07 · G06 | VBA `dlgPrintDocuments` подтверждает EPL, COM `9600,n,8,1`, выражение `.Handshaking = 2 - comRTS`, `RTSEnable=True`, `RThreshold=1`, `SThreshold=1` и проверку входного буфера после отправки. В Immediate Window работающего Access подтверждены `comRTS=2` и `Forms("dlgPrintDocuments").Controls("MSComm").Object.CommPort=1`: фактический Handshaking равен `0` (без аппаратного handshake), рабочая форма настроена на COM1; закомментированное в VBA `CommPort=2` не действует. Модель/носитель нужно снять с рабочего места. | Перенести тот же EPL и последовательность COM-отправки в Windows agent; проверить на Zebra один согласованный barcode и переключение Access ↔ agent. |
| P08 · G07/G08 | Исправление скана восстанавливает прежний статус, но audit-вызовы DELETE-триггера закомментированы. `modMeniu.DeleteItemFromProductionMovemementDocument` удаляет выбранную успешную строку журнала, не обязательно последнюю; fixture GT сейчас ошибочно ограничивает кнопку последним сканом. | Сверить права и запрет при последующих документах; определить receipt с actor/до/после без изменения общего триггера. Перед live-командой исправить fixture-правило по доказанному контракту. |
| P09 · G09/G10/G13 | Полный контракт остановок, ремонтов, выдачи и внешних side effects ещё не обследован. | Прочитать связанные процедуры/триггеры/формы; не включать команду до закрытия соответствующей строки реестра. |
| P10 · G12 | SQL write-off подтверждает движение внутри процедуры, но фактическое место вызова Access и политика повторов ещё не доказаны. | Сверить все вызовы/сообщения и движения; не проводить повторно на основании текста UI. |
| P11 · G14 | Sales preview читает сохранённую формулу и не проверяет новую до сохранения. | Выделить узкий trusted test-before-save API либо общий чистый calculator; не писать тестовую формулу в production. |
| P12 · G15 | Общие формы отчётов содержат и производственные, и коммерческие/финансовые действия. | Составить закрытый список реально используемых производственных отчётов/Excel, не переносить остальную платформу. |
| P13 · G11 | Read API показывает документы `TAB_ProductionOutputDocuments`, включая операцию `Sustabdytas`, и строки `TAB_BlindRepairments`; последняя таблица сейчас пуста. Полный набор иных производственных событий ещё не доказан. Старая `sp_BlindDescriptionByBarCode` не проверяет `Loc_leidimas`; web-запрос фильтрует филиал явно. | Сверить по barcode Access/web для остановки, ремонта и повторной выдачи; проверить права на все документы до объявления временной шкалы полной. |
| P14 · G10 | В текущей общей SQL-базе `TAB_BlindRepairments`, `v_Garantiniai`, `v_GarantiniaiUnknown` и `v_NotFinishedWarranties` содержат 0 строк. Read API проверен на схеме и под `TERMINAL\d.bykovas`, но сверить реальную карточку, фильтры и прямой доступ к чужому ремонту пока не с чем. | Получить допустимый эталон существующего ремонта или согласованный Testavimas-сценарий регистрации; до этого не считать G10 принятой и не включать запись. |
| P15 · G01/G09 | Access вызывает `sp_CancellBlindConfirmation @iBlindID int`, тогда как `ParduotiGaminiai.ParduotoGaminioID` имеет тип `bigint` и уже достиг 2 152 012 475 (> 2³¹−1). Отмена подтверждения для новых изделий не помещается в параметр процедуры; это отдельное действие от перевода в `Sustabdytas`. | Подготовить совместимый `bigint` контракт и проверить все его эффекты в Access и web; изменение общей процедуры согласовать отдельно, до этого команду не включать. |
| P16 · G08 | `sp_cbo_AssignedStateID_dlgNewProductionOutputDocument` под `TERMINAL\d.bykovas` возвращает четыре разрешённые операции GT, под `sa` — ноль. Формальный admin bypass меню 41 не даёт права на выбор GT-операции в legacy. Read-only GT список совпадает с Access по фильтру автора и текущего месяца, включая его окно по дню месяца; в начале месяца это меньше четырёх календарных суток. | Не расширять список операций искусственно. Перед записью GT определить с владельцем право admin/`sa` и сверить создание/продолжение документа через Access; отдельно решить, менять ли старое окно без расхождения с Access. |
| P17 · G07/G08 | Живой `T_TAB_ProductionOutputDocumentDetails_AssignBlindState` при INSERT меняет `ParduotiGaminiai.BusenosID`, но не вызывает `fn_CheckStateChange` и не проверяет `Loc_leidimas`. Access делает обе проверки до INSERT; read-only список кандидатов не защищает будущую команду от прямого запроса или гонки. | Перед каждым live INSERT под mapped login в одной SQL-транзакции заблокировать документ и изделие, повторно проверить меню/владельца GT, филиал, разрешённый целевой статус и `fn_CheckStateChange`, затем вставить ровно один barcode; проверить конфликт с параллельным Access и receipt после потери ответа. До этого запись сканов выключена. |

Для тестовых действий с материалами, глобальными настройками, отправкой и реальным COM используется отдельно согласованный образец; серия Testavimas сама по себе не изолирует общие остатки и оборудование.
