# Задание дизайнеру: «Vertikalios · Trapecija»

## Результат

Спроектировать дополнение к **Gamyba → Documents → Production documents**: оператор выбирает изделие, уточняет автоподставленные размеры, видит реальные длины каждой ламели, сохраняет и печатает расчёт. Потребители: оператор подготовки производства, резчик ламелей, сборщик.

Gamyba уже работает с настоящими заказами и GU. Сохраняем текущую оболочку и навигацию. Источник стиля: [UX handoff](../../ux/lkvitai-mes-ux-handoff.html), присланные пользователем скриншоты текущей Gamyba. [Прототип](preview.html) показывает предлагаемую компоновку и поведение; расчёт основан на Excel.

## Размещение

- Новый пункт **Vertikalios · Trapecija** непосредственно после **Vertikalios**. Существующий отчёт Vertikalios остаётся доступен.
- Рекомендуется отдельная запись каталога: 13 существующих + 1 новая. Заголовок показывает фактическое число, не строку «13» навсегда. Счётчик рядом с пунктом — число подходящих строк текущего GU; количество изделий показываем отдельно.
- Три рабочие области: компактный каталог слева, выбор изделия + форма + отчёт по центру, сохранение/печать/версии справа. Ширину центральной области отдаём схеме и таблице.
- На ширине около 1280 px правые действия переходят в верхний toolbar. На планшете каталог сворачивается в selector. На телефоне ввод в одну колонку, схема с масштабированием и таблица с горизонтальной прокруткой. Отдельный мобильный производственный процесс не изобретаем.

## Выбор изделия и input-поля

Путь из GU сохраняет его контекст и ограничивает выбор его составом. В Documents доступны выбор заказа и конкретного изделия/штрихкода. Одного номера заказа недостаточно: в нём могут быть несколько разных трапеций.

Верхняя строка: **GU → заказ → изделие**, материал/цвет и количество. Ниже постоянная компактная форма, а не спрятанная настройка PDF:

| Поле | Начальное заполнение | Управление / поведение |
|---|---|---|
| Тип A/B | Управление изделия в заказе | Segmented control A/B, рядом расшифровка управления |
| Ширина ламели | Материал: 89 или 127 мм | Segmented control / select 89/127, можно уточнить вручную |
| AD, ширина | Ширина изделия в заказе | Числовой input, мм |
| CD, большая высота | Отдельный параметр большой стороны; иначе общая высота изделия | Числовой input, мм |
| AB, малая высота | Параметр малой стороны, если заполнен | Числовой input, мм; при отсутствии пустой |
| Выступ крайней ламели | Параметр выступа, если есть | Числовой input, мм; явный ноль допустим |
| Высокая сторона | Отдельные достоверные данные ориентации, если есть | Левая / правая, явно обозначенный вид из помещения |

Ширина и две высоты визуально сгруппированы под маленькой размерной схемой AD/AB/CD. Под полем — компактная подпись **Из заказа**, **Из материала**, **Введено вручную**, **Не заполнено**. Подставленное значение можно изменить. После ручного изменения появляется действие «Вернуть из заказа/материала»; новая автозагрузка не перетирает уточнение без явного действия.

Обычные input — нейтральные, focus — teal. Жёлтые поля Excel не переносим ярко-жёлтыми: пустые обязательные размеры выделяем существующим sand/warn, ошибки — danger. Источник значения обозначается текстом, не только цветом.

Если материал говорит 127, а параметр изделия 89, показываем обе величины и конфликт. Подстановка из названия материала без структурированного признака не считается достоверной. Для A/B не угадываем по левому/правому управлению. Нулевые высоты/ширина означают необходимость заполнения, а нулевой выступ — допустимое значение.

При отсутствии выступа для A предлагаем явно выбрать «0 мм, без выступа» либо ввести размер. Для B поле обозначается «не используется расчётом Excel» и не влияет на результат. Не превращать пустые обязательные размеры в нули.

Пример начального состояния по последнему скриншоту пользователя: AD=1970 пришло из заказа, AB/CD пустые, ширина ламели 127 подставлена. Показать места для ввода, схему с размерными обозначениями без рассчитанных ламелей и недоступную печать. Отрицательные длины, как при нулевых высотах в старой книге, не выводить как готовый результат.

## Расчёт и схема

После изменения валидных input обновляются расчёт и схема; пока запрос идёт, показывается «Пересчитываем», печать предыдущего результата недоступна. Не нужно заново выбирать заказ после каждого изменения. Над отчётом — статус «Расчёт изменён, версия не сохранена» и ссылка на последний сохранённый вариант.

Основная схема — фронтальный вид жалюзи с наклонной направляющей и **n отдельных ламелей**, а не изображение трапеции из библиотеки. Каждая ламель имеет рассчитанную длину. Вертикаль остаётся вертикалью, нижняя линия общая. Шаг по направляющей и горизонтальный шаг не смешивать.

Обязательные обозначения:

- AD — ширина; AB/CD — введённые высоты проёма/изделия, отдельно от длин ткани.
- BC — диагональ; рез рамы — отдельное значение с подписью. Это не одна величина.
- A/B и положение управления; высокий край; направление сборки вверх; вид из помещения.
- Номера ламелей `n1…nN`, нумерация от короткой к длинной. При зеркалировании номера физически переходят на другую сторону вместе с ламелями.
- Подсказка выбранной ламели: номер, расчётная длина до +45, длина реза с +45. Дополнительные +27 относятся к расходу, на чертёж ламели их не добавлять.

Hover/click по ламели выделяет соответствующую строку. Click по строке выделяет ламель. Поддержать клавиатуру и видимый focus. Выделение teal; остальные ламели нейтральные с тонким контуром. Цвет материала можно указать образцом, но он не должен ухудшать читаемость размеров.

Дополнительный режим «Раскрой»: все заготовки выровнены по одной верхней линии; длины соответствуют `cut[i]`. Он помогает резчику сравнить длины. Номера остаются теми же. Это не оптимизация раскладки по рулону.

Масштаб X/Y одинаковый; вся геометрия помещается через viewBox/zoom. При 60–78 ламелях не накладывать все подписи: показывать номера с интервалом, всегда крайние и выбранный; полный список доступен в таблице. На PDF при необходимости делать увеличенные фрагменты. Схема не является лекалом 1:1.

В прототипе расположение ткани показано схематически по вычисленным длинам; точное положение фурнитуры относительно AB/CD нужно согласовать на реальном изделии. Не рисовать выдуманные монтажные допуски как доказанные.

## Состав отчёта

1. Шапка: «Vertikalios · Trapecija», GU, заказ, изделие/штрихкод, материал, количество, A/B, 89/127, дата, автор, версия документа.
2. Компактная строка **использованных** размеров AD/AB/CD, выступа и ориентации; признак ручного уточнения.
3. Схема и технологическая сводка: диагональ BC, рез рамы, FIKSAS и размер до механизма, шаг и рез детали шага, удлинитель, количество ламелей.
4. Таблица: № ламели, длина реза с +45 мм, количество на выбранные изделия. Длину до +45 показывать в подробностях/дополнительной колонке, чтобы резчик не перепутал две длины.
5. Итоги: число изделий, ламелей на комплект и всего, расход на комплект и всего. Сноска «Расход включает дополнительный припуск 27 мм на ламель». Не называть его отходами, поскольку назначение не подтверждено.
6. Подвал: версия расчёта/технологического профиля, версия документа, страница X/Y. Технический hash доступен в деталях версии, а не занимает главный экран.

Новый формат — **A4 landscape** для схемы и таблицы рядом/под ней. Это предложение вместо portrait в исходном Excel. Не уменьшать шрифт ниже 9 pt ради одной страницы. Для длинного списка — продолжение с повторной шапкой, идентификатором изделия и нумерацией ламелей. Одна геометрия изделия не смешивается с другой; количество одинаковых изделий оформляется колонкой количества.

Печатный документ — белый фон, нейтральные тонкие линии, чёрный текст, моноширинные размеры. Работает в чёрно-белой печати. Панели навигации, input и действия не печатаются. У готового PDF и preview совпадают цифры, порядок и геометрия.

## Действия и состояния

Основные: «Сохранить расчёт», «Сформировать PDF», «Печать», «Открыть сохранённую версию». После изменения input состояние становится «Не сохранено». На печать идёт конкретная сохранённая версия. Просмотр/пересчёт не меняет статус производства или склад.

Нужно отрисовать: пустой GU/NoData; загрузку заказа; автозаполненную форму; недостающие AB/CD; ручное уточнение; конфликт источников 89/127; неправильные размеры; ограничение удлинителя; пересчёт; готовый несохранённый расчёт; сохранённую версию; изменившийся заказ; просмотр старого PDF; ошибку API/PDF; отсутствие прав; много изделий и длинный список ламелей.

Значения технологического профиля 5/25/16/15/130, +6/+45/+27 находятся в раскрываемых деталях. Оператору не требуется переписывать их для каждого заказа. Редактирование технологии не является частью редактора печатного шаблона.

## Deliverables и приёмка

- Desktop 1440/1920, узкий desktop/tablet, A4 landscape и продолжение.
- Готовые состояния выше и интеракции выбора/изменения/сохранения/печати.
- Согласованный масштаб, базис нумерации и подписи A/B/AB/AD/CD.
- На примере A из Excel: 26 ламелей, печатные крайние длины **1605 / 1794 мм**, расход **44.893 м**. Изменение CD изменяет длины/рисунок/расход.
- На примере B: 14 ламелей, **1689 / 2115 мм**, расход **27.006 м**.
- Визуальная система из handoff: dark header, нейтральные поверхности, teal; компактные строки около 30 px, mono/tabular для чисел. Без декоративных цветов и oversized cards.
- Финальные подписи EN/LT; все строки приложения, ошибки, aria-label, SVG-подписи и PDF-лейблы подготовить для `.resx` и `IStringLocalizer` по [i18n](../../i18n/README.md). Русский язык этого задания не задаёт новую локаль приложения.
